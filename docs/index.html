vt-helper

A tiny, zero-dependency helper for the browser View Transitions API, with automatic fallback for unsupported browsers.

Get started View on GitHub

Why

document.startViewTransition is great, but every call site ends up rewriting the same feature-detection boilerplate. vt-helper wraps it once so your code looks the same whether or not the browser supports it — on unsupported browsers your DOM update still runs, you just lose the animation.

Install

npm install vt-helper
import { transition } from 'vt-helper';

button.addEventListener('click', () => {
  transition(() => {
    document.body.classList.toggle('dark');
  });
});

Checking View Transitions support…

1. Theme toggle

Wrap a state change in transition(). Supported browsers cross-fade the change automatically; the fallback just applies the class.

Card title

Click the button to toggle dark mode with a view transition.

import { transition } from 'vt-helper';

card.style.viewTransitionName = 'demo-toggle'; // scope the animation

button.addEventListener('click', () => {
  transition(() => {
    card.classList.toggle('dark');
  });
});

2. Reorder a list

Each list item keeps a stable view-transition-name, so the browser animates items sliding to their new position.

3. Sequenced steps

transitionSequence() runs each step's transition only after the previous one has fully finished, so steps never overlap.

Step 0 of 3 
import { transitionSequence } from 'vt-helper';

await transitionSequence([
  () => setStep(1),
  () => setStep(2),
  () => setStep(3),
]);

API reference

transition(callback) → TransitionHandle

Wraps document.startViewTransition(callback). callback may be sync or return a Promise. On unsupported browsers, runs callback via requestAnimationFrame (falling back to a microtask outside the DOM) and returns a handle whose promises resolve once the callback settles. 

interface TransitionHandle {
  readonly finished: Promise<void>;
  readonly ready: Promise<void>;
  readonly updateCallbackDone: Promise<void>;
  skipTransition(): void;
}

On unsupported browsers, ready, finished, and updateCallbackDone all resolve (or reject) together once callback settles, and skipTransition() is a no-op.

transitionSequence(callbacks) → Promise<void>

Runs an array of TransitionCallbacks in order, calling transition() for each and awaiting its finished promise before starting the next. If a step throws or rejects, the sequence stops and the returned promise rejects with that error.

isViewTransitionsSupported() → boolean

Feature-detects document.startViewTransition. Useful if you want to branch your own logic instead of relying on the built-in fallback.

Browser support

The View Transitions API is supported in recent Chromium-based browsers; see caniuse for current coverage. Everywhere else, vt-helper's fallback runs your callback with no animation, so your DOM updates are consistent across all browsers — you only lose the transition effect, never the update itself.
